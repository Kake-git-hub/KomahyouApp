## 作業 A: 休みの講師を同じコマへ手で置いたら、休みをコマ全体で解除する(進行中テーマ台帳 `teacher-rest-hand-placed-elsewhere`)

**いまの挙動**: 休みの自動解除は「休みにした机に、休んだ本人を手で置き直したとき」だけ(机単位。`teacherRest.ts` の `releaseTeacherRestIfSameTeacherPlaced`・
`docs/spec-template-conflict-v2.md` §9-19・§2-4)。講師 X を休みにして代わりの講師 Y を置き、X を同じコマの**別の机**に手で置くと、X の休みの記録が Y の机に残る
(X は「休み」なのに盤面に居る、という食い違った状態)。

**決まったこと**: X を同じコマ(日付×時限)のどこかの机へ**手で**置いたら、そのコマにある X の休みの記録を全部消す(どの机に残っていても)。

**進め方**
1. `spec-curator`: §9-19・§2-4・§9-23 の「未決・オーナー判断待ち」の文を決定に書き換える(決定記録にオーナー回答 2026-11-11 を残す)。決める細部:
   - 解除する経路 = 講師を手で置く経路すべて(講師メニューの保存・長押しドラッグの移動と入れ替え・保留の下の行の採用)。いま `releaseTeacherRestIfSameTeacherPlaced` を呼んでいる
     3 か所(`deskTeacherAssignment.ts`・`ScheduleBoardScreen.tsx` の講師の移動・`templatePendingResolution.ts`)が出発点。呼び出しの漏れが無いか兄弟監査する。
   - 自動で講師が入る経路(テンプレの反映・講習の自動割振・QR 提出の反映)は対象外(休みが勝つ・今までどおり置かない)。
   - 代わりの講師 Y の机はそのまま(Y は残る・グレーの「休」の表示だけ消える)。休みの記録が消えるので、次のテンプレ反映では X はテンプレどおりに置かれうる。
     そのとき Y の机(X のテンプレの机)がどうなるかは、既存の「手で入れた講師が勝つ」(§2-3)の結果を確かめて仕様に書く。**使い勝手に響く点が出たら、懸案と妥協案をオーナーへ出す。**
   - 元に戻す(Undo)で休みの記録も戻ること。
   - すでに盤面に残っている食い違った状態(本番 2 校に何件あるか)を、読み取りだけで数える(`owner-postmortem-expectations` の「影響件数の事前実測」)。直し方(起動時に掃除するか・そのままか)は件数を見て決める。
2. `dev-fix`(テスト先行・INV-02／INV-01／INV-03 の完了定義 4 点): 権威関数を 1 つにする(机単位の関数を、コマ全体を見る関数に置き換えるか包む。数え方を 2 つ作らない)。
   - `inv02-manual-edit-persistence.matrix.test.ts` の「休みの兄弟 (a)(b)」(題名に「今の挙動・オーナー判断待ち」)は、決定後は「その状態が手の操作で作れない」ことの行に置き換える
     (既存の行の書き換えになるので、`docs/spec-invariants.md` の改定を同じ push に入れる。CI の INV 改定ガード)。
   - `templateDeskOrderRestore.ts` の `fallbackUsable` の所のコメント(2026-11-11・オーナー判断待ち)を、決定に合わせて直す。合流の判定そのものは、食い違った状態が作れなくなれば今のままでよい
     (`isTeacherRestedInCell` へ替えると、授業の手がかりの経路と食い違って 1 回目の保存で離れ 2 回目で戻る。経緯は進行中テーマ台帳の notes)。
3. 確認リストに項目を足す(講師を休みに → 代わりの講師を置く → 休みの講師を同じコマの別の机に手で置く → グレーの「休」が消える・元に戻すで戻る)。
4. 画面の自動巡回を回してから main へ。済んだら進行中テーマ台帳の行を消す。

## 作業 B: 画面の自動巡回 第 2 段の残り(進行中テーマ台帳 `ui-patrol-stage2`)— この順で進める

設計は `docs/test-strategy.md` の「画面の自動巡回(層 5)」、手順は `docs/runbooks/ui-patrol.md`、道具は `tools/ui-patrol.mjs`・`tools/ui-patrol/`、メモは `.claude/memory/komahyou-ui-patrol.md`(踏んだ罠)。

| 順 | すること | ねらい・注意 |
|---|---|---|
| 1 | **台本を足す**。この順で 1 本ずつ: (a) テンプレを実際に変えて保存(生徒を 1 人足す・講師を替える・机を消す) (b) 出欠(休み・振無休・出席・振替先を決める) (c) 講師の移動と入れ替え・講師の休み (d) 休日設定と解除・丸ごと振替 (e) 講習の自動割振 | 事故が続いたテンプレ保存の周りを先に厚くする。台本ごとに「変わってよい範囲」を `scenarios.mjs` に定義し、効くことを「わざと 1 行壊す → `[変・新]` が出る」で確かめる。(c) は作業 A の挙動が決まってから |
| 2 | **過去の事故の日の形を、決まった一覧で流す**(`--key` の一覧を設定ファイルに持ち、1 つの引数で順に流す) | 安く効く。まず緑が丘 2026-11-10T03-00(テンプレ保存の事故)。日次バックアップは 400 日残る。時間が延びるので既定には入れず、テンプレ・再反映を触った変更のときだけ |
| 3 | **でたらめ操作を育てて既定で数十手流す**(`--random`・土台あり) | 1 で足した操作をでたらめ操作の部品にも入れる。乱数の種は固定し、見つけた所見は種と手数で再現できるようにする |
| 4 | **毎晩の自動実行と結果の報告** | 最後。GitHub Actions に Playwright と読み取り専用の鍵が要る(鍵を Actions の secret に置くことはオーナーの判断)。オーナー決定「毎朝の健診には入れない」と別物として設計し、着手前に案を出す |

**ついでに直す候補(レビューの軽い指摘の残り)**
- 「講師を消した机」の判定を、消した講師の ID の顔ぶれ(コマごとの多重集合)で比べる。今は数だけなので、同じコマで 1 つ消えて 1 つ増えた形を見分けられない(`tools/ui-patrol/checks.ts`)。
- 変更前との比較の鍵が、同じ台本の中の別の手順を区別しない。「ほか n 机」にまとめた所見は中身の入れ替わりに気づけない(`tools/ui-patrol/baseline.mjs`)。
- `--baseline <report.json>` に、台本・移動の数・乱数の種・日付の違う報告を渡したら断る(報告に条件を記録する)。
- `--baseline-ref` の取り出しの最中に止めると、取り出し先がスクラッチ領域に残る(次の実行で消える)。
