# 矛盾配置（置けない授業を机を増やして見せる）— 仕様案と実装方針（下書き・2026-10-25）

> 状態: **オーナー確認待ちの下書き**。承認後に spec-curator が `docs/spec-template-behavior.md` §I（仮）へ正本化し、
> `docs/spec-invariants.md` に INV を 1 本足す。コードは未着手。
> 出典: オーナー指示 2026-10-25「満席などであふれる場合、新しい時限に自動で机数を一つ増やしそこに割振り、黄色背景・赤色文字で
> 矛盾配置であることをわかりやすく」「室長が行った操作でどうしても入らないケースは勝手に処理すると室長が混乱する」。決定記録 46・47。

## 0. 一言で

自動処理（テンプレ保存・丸ごと振替・休日解除・再マージ）が授業を本来の机に置けないとき、**未消化へ積む・希望回数 −1・黙って置かない・消す**へ逃がさず、
そのコマの**末尾に机を 1 つ増やして置き、黄色背景・赤文字で「矛盾配置」と示す**。室長が見て、手で別の机・別の日へ動かして解消する。
解消するまで授業は盤面に居続ける（日程表・在庫・講師日程表では普通の授業として数える）。

## 1. 原則（判断の物差し）

1. **消さない・隠さない・勝手に別の場所へ逃がさない。** 置けないなら盤面に「置けなかった」と見える形で残す。
2. **室長の手作業が最優先。** 室長が手で置いた授業・講師は、自動処理が動かさない（INV-02）。動かすべきはテンプレ側・自動側。
3. **保留（緑 2 行）と役割を分ける。** 保留＝同じ机に候補が 2 つ（室長がどちらかを選ぶ）。矛盾配置＝置く机が無い（室長が置き場所を決める）。
   同じ机の取り合いは今までどおり保留で、矛盾机は作らない。矛盾机は保留にならない・保留机は矛盾にならない。
4. **会計は中立。** 矛盾机の授業は普通の授業として在庫・希望回数に数える（置いた振替は origin を消化する）。矛盾配置の作成・解消で残数は動かない。
5. **不動点。** 矛盾机がある盤面を再マージ・再保存しても、矛盾机が増えない・二重にならない（INV-03）。

## 2. 用語とデータ

- **矛盾机**: 机番号（教室設定の机数）の**外**に足した机。`DeskCell` に印を持つ。

```ts
// types.ts
export type ConflictPlacementReason =
  | 'transfer-follow-full'        // Phase 1: Q40-2 丸ごと振替の振替元に足した生徒の振替先が満席
  | 'slot-follow-full'            // Phase 3: 決定記録 46 時限変更の追従で新しい時限が満席
  | 'whole-day-transfer-existing' // Phase 2: 丸ごと振替の振替先に室長が置いていた体験・増コマ・手動追加（空き机にもずらせない）
  | 'holiday-release-seat-taken'  // Phase 2: 休日解除で戻す席に別の生徒
  | 'remerge-no-desk'             // Phase 2: 再マージでテンプレの授業を置く机が無い

export type DeskCell = {
  …既存…
  /** 矛盾配置の印。ある机は机数の外の臨時机。空になったら正規化が消す。 */
  conflictPlacement?: { reason: ConflictPlacementReason; createdAt: string; note: string }
}
```

- 机 ID: `${cell.id}_desk_c1`, `_desk_c2` …（既存の `_desk_<番号>` と形を変える。`deskSort.parseDeskOrder` の `/_desk_(\d+)$/` に
  掛からず末尾に並ぶ。既存の ID 生成・解釈はそのまま）。
- 席は 2 つ（普通の机と同じ）。同じコマで 3 人以上あふれたら矛盾机を 2 つ目まで足す（上限は設けない）。
- `note` は表示用の理由文（例「11/29 2限 が満席のため」「丸ごと振替の振替先に手で置いていた授業」）。ツールチップと一覧に出す。

## 3. 正規化（土台・全教室共通・フラグに依らない）

今は `normalizeWeeksDeskCount` / `computeWeekAvailability` が各コマの机を**教室の机数にそろえ、余分は切り落とす**。
これを「机数ぶんの普通の机 ＋ 印のある矛盾机（順序保持）」に変える。

- 矛盾机は机数の後ろに並べる。番号は付けず、盤面では「矛盾」と表示する。
- **空の矛盾机は消す**（生きている生徒・講師・出欠記録・メモのどれも無い）。室長が動かして空になったらその場で消える。
- 印の無い余分な机（旧データ・バグ）は従来どおり切り落とす。
- 本番教室（フラグ OFF）では矛盾机を**作らない**ので見た目は変わらない。ただし正規化・描画・保存の土台は全教室共通で入れる
  （片側だけフラグで切ると、フラグ OFF のクライアントが矛盾机付きの保存データを読んだときに切り落として授業を失う）。

## 4. 作る条件（適用先とフェーズ）

| # | 操作 | 置けない条件 | 今 | 矛盾配置後 | フェーズ |
|---|---|---|---|---|---|
| 1 | テンプレで丸ごと振替の元の日に生徒を足す（Q40-2） | 振替先のコマが満席（同じ机→別の机→講師なしの机まで無い） | 未消化へ（休日でなければ台帳に origin 1 件＝INV-06 の唯一の例外） | 振替先のコマの矛盾机へ振替として置く。台帳には積まない（在庫中立）。既知の限界 L-5（積んだのに残数が増えない消失）が無くなる | 1 |
| 2 | 丸ごと振替 | 振替先に室長が置いていた**体験・増コマ・手動追加の通常** | 消して希望回数 −1 | 振替先のコマの**空き机へずらす**。空き机が無ければ矛盾机へ。**テンプレ由来の通常授業だけは従来どおり**（消して −1・オーナー決定）。振替・講習は従来どおり未消化へ戻す | 2 |
| 3 | 休日解除 | 戻す席に別の生徒が居る（'seat-taken'） | 戻さず、記録が席の生徒の下に隠れる | 同じコマの矛盾机へ戻す | 2 |
| 4 | 再マージ（読み込み・保存直後） | テンプレの授業を置く机が無い | 黙って置かない | 矛盾机へ置く（管理授業の印を保つ＝次の再マージで二重に作らない） | 2 |
| 5 | テンプレで時限を変えたときの追従（決定記録 46） | 振替先の新しい時限が満席 | （未実装） | 矛盾机へ | 3 |

対象外（今のまま）: 同じ生徒が同じコマに居る（Q21-11）、丸ごと振替で行き先が分からず −1（Q35-8）、根拠を失った振替を消す（Q40-1）、
休日解除で別の日の振替・講習を消す、講習の自動割振りで候補なし、Q36 の写しの巻き戻し、Q38 手動追加をテンプレが外す。
Q40-2 の 'duplicate'（同じ生徒がそのコマに生きている）と 'no-target-cell'（振替先のコマが無い）は従来どおり未消化（要確認 §10-6）。

## 5. 表示

- **盤面**: 矛盾机の行は黄色背景（例 `#fff3b0`）、講師欄・生徒名を赤文字（例 `#c62828`）、左に赤の縦線。机番号の位置に「矛盾」。
  ツールチップに `note`（理由）と作成日時。保留の緑・ずらした講師の緑とは別のクラス（`sa-desk-conflict`）。
- **上部の帯**: 画面上部に「矛盾配置 n 件」のバッジ（未消化振替・未消化講習のボタンと並べる）。押すと一覧モーダル（日付・時限・生徒・科目・理由・
  「そのコマへ移動」）。矛盾机は何週も先に散らばるので、盤面を眺めるだけでは見つからない（棚卸しで判明した共通の弱点）。
- **テンプレ保存の確認の画面と保存後の 1 行**: 「置き換え n机・保留 n机」に「矛盾 n机」を足す。「詳細」に生徒ごとの理由行（kind: 'conflict-placed'）。
- **丸ごと振替・休日解除の確認ダイアログ**: 「矛盾配置にする授業: n 件」と名前。
- **机 PDF・共有画面**: 矛盾机の行を出す。色は要確認（§10-1）。
- **生徒日程表・講師日程表・保護者ページ**: 普通の授業として出す（印は出さない。講師が居なければ講師日程表には出ない＝今の講師なし机と同じ）。

## 6. 操作

- 矛盾机の生徒は普通にドラッグ・移動・削除・出欠・メモができる。別の机・別の日へ動かせば解消。
- **矛盾机への手動ドロップ・生徒追加は禁止**（「矛盾配置の机には置けません。別の机へ置いてください」）。矛盾机は解消待ちの置き場であって、普通の机の代わりにしない（要確認 §10-2）。
- 講師を付けるのは可（付けるまで講師日程表に出ない。講師欄に「講師を付けてください」の注記）。
- 並べ替え（上に詰める・同席番）は矛盾机を動かさない（常に末尾）。詰め直し・講習の講師自動割当・QR 自己修復は矛盾机を空き机に数えない。

## 7. 他の処理との関係（矛盾机がある盤面で）

| 処理 | 扱い |
|---|---|
| テンプレ保存（差分反映） | 矛盾机はテンプレの机番号の外なので突き合わせない（参照ごと据え置き）。ただし「同じ生徒が同じコマに居る」判定（Q21-11）には入れる＝テンプレが同じ生徒を二重に置かない。テンプレが同じ生徒×科目の席を同じコマに用意しても**自動で戻さない**（一覧から室長が移す・要確認 §10-3） |
| 再マージ | 同上。#4 で作る矛盾机は管理授業の印を保ち、次の再マージは「生きている同じ授業」として認識して二重に作らない（不動点） |
| 丸ごと振替 | 振替元・振替先のどちらかに矛盾机があれば**止める**（「矛盾配置を解消してから」。保留があるときと同じ扱い）。#2 で振替先に矛盾机を作るのは、止める判定の後 |
| 休日設定 | 普通の机と同じ（振替は在庫へ返す等）。空になった矛盾机は消える |
| 休日解除 | #3 |
| 在庫（未消化振替・講習） | 矛盾机の授業も普通に数える（振替は origin を消化）。作成・解消で残数は動かない |
| 保存・バックアップ・復元・教室コピー | JSON をそのまま通す（机数の検証が無いことを要確認。functions `saveClassroomSnapshot`） |
| 退塾掃除・名簿改名の反映 | 普通の机と同じ |
| 操作の記録（operationTrace）・保存履歴 | 作成を 1 行記録 |

## 8. 実装方針（段階）

### Phase 0 — 土台（1 PR・全教室共通の変更を含む・機能フラグ `conflictPlacement` を足す）
1. `types.ts`: `conflictPlacement` を足す。`conflictPlacement.ts`（新規・純関数）: `placeStudentIntoConflictDesk(cell, student, reason, note)`／
   `placeTeacherIntoConflictDesk`（Phase 3 用）／`isConflictDesk`／`collectConflictPlacements(weeks)`（一覧・件数）／`pruneEmptyConflictDesks`。
2. 正規化 2 か所（`normalizeWeeksDeskCount`・`computeWeekAvailability`）を「机数＋印のある矛盾机」に変更。空の矛盾机を消す。
3. 盤面の描画（`BoardGrid`）: 行数を「机数＋そのコマの矛盾机の最大数」に。クラス `sa-desk-conflict`・CSS・ツールチップ・「矛盾」ラベル。
   ドロップ禁止・生徒追加メニュー非表示。PDF（`pdf.ts`）と共有画面（`BoardShareScreen`）・日程表 HTML（`scheduleHtml`）の行対応。
4. 上部バッジ＋一覧モーダル（`collectConflictPlacements` を読むだけ）。
5. 差分反映・再マージ・並べ替え・詰め直し・空き机判定（`deskSort`・`isDeletedTeacherTombstone` 周り・QR 自己修復・講習の講師自動割当）が
   矛盾机を素通りする／空き机に数えないガード。丸ごと振替の事前ブロック。
6. テスト: 正規化（残す・空なら消す・印なしは切る）、再マージ・差分反映の不動点（矛盾机が増えない・二重にならない）、Q21-11 の二重防止、
   描画配線（クラス・行数・PDF の行）、並べ替えで動かない、丸ごと振替のブロック、保存往復（JSON）で消えない。
   `desks.length` / `desks[deskIndex]` の前提箇所（ScheduleBoardScreen 45・他 14）を 1 件ずつ点検して、机数固定前提のものに矛盾机の扱いを明記。

- マトリクス `inv06-template-transfer-follow`: 満席の 2 行（休日でない・休日）を矛盾配置の期待に改定＋取り下げ（M-2）の行を見直す。
- 確認リスト tp-49 の満席の文を書き換え。

### Phase 2 — 丸ごと振替の振替先の既存授業／休日解除／再マージ（1〜2 PR）
- `computeWholeDayTransfer`: 振替先の体験・増コマ・手動追加を空き机へずらし、無ければ矛盾机。テンプレ由来の通常は従来どおり（消して −1）。
  振替・講習は従来どおり未消化へ。確認ダイアログに件数と名前。マトリクス `inv06-whole-day-transfer` を拡張。

- `mergeManagedWeek`: 置く机が無い管理授業を矛盾机へ（印を保つ）。再マージ 2 回の不動点。

### Phase 3 — 決定記録 46（時限変更の追従）＋印だけの項目

### 見積り
Phase 0 が最も大きい（机数固定の前提を解く・描画 4 系統・テスト）。Phase 1 は小。Phase 2 は中。Phase 3 は中。
各 PR は開発用教室・テスト教室だけで出し（フラグ）、確認リストに項目を足してテスト担当に見てもらう。

## 9. 保証（台帳に足す INV の案）

- **新 INV（番号は台帳に従う）「矛盾配置は黙って消えない」**: 矛盾机の授業は、室長の操作（移動・削除・休日設定・丸ごと振替の処分）以外では消えない・動かない。
  矛盾机は空になったときだけ消える。再マージ・テンプレ保存・並べ替え・詰め直し・名簿更新は矛盾机を増やさず減らさず動かさない。
- 既存 INV との関係: INV-02（手置きの不可侵）… 矛盾机は手置きと同じ扱い。INV-03（不動点）… 矛盾机を含めて固定。INV-06（在庫中立）… 例外を縮める。
  INV-10（反映日より前は不変）… 反映日より前のコマには矛盾机を作らない。INV-12（同じコマに同じ生徒は 1 か所）… 矛盾机も数える。

## 10. オーナーに決めてほしい点

1. **机 PDF・共有画面での見せ方**: 黄色背景のまま印刷する／「【矛盾】」の文字だけにする（提案: 黄色のまま。紙で配る盤面でも気づける）。
2. **矛盾机への手動ドロップ**: 禁止（提案）／許可（許可すると普通の机の代わりに使われ、解消されない）。
3. **テンプレが同じ生徒×科目の席を同じコマに用意したとき**: 自動で戻す／戻さず室長が一覧から移す（提案: 戻さない。「勝手に処理しない」の原則どおり。戻すなら理由行を出す）。
4. **講師**: 矛盾机には講師を自動で付けない（提案）。付けるまで講師日程表に出ない。
5. **Phase 2 の「空き机へずらす」の優先順**: 講師が居る机→講師なしの机（Q40-2 と同じ・提案）。
6. **Q40-2 の 'duplicate'（同じ生徒がそのコマに生きている）と 'no-target-cell'**: 従来どおり未消化（提案）／矛盾配置。
7. **丸ごと振替のブロック**: 矛盾机がある日は止める（提案・保留と同じ）／止めずに矛盾机ごと移す。
