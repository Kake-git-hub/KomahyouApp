## 1. 原則

1. 自動処理が授業を本来の机に置けないとき、**消さない・隠さない・勝手に別の場所へ逃がさない**。その机の下段（保留・緑）に残し、室長が動かすか採用で片づける。
2. 優先順位は **2 行表示（保留） > 別の仕組み**。同じ番号の机がある限り保留で表す。別机は作らない。
3. 室長の手作業が最優先（INV-02）。動かすのはテンプレ側・自動側。
4. 会計は中立。下段の授業も在庫・日程表で普通に数える（`collectLessonExplanationFacts` と在庫の走査は既に下段を含む）。
5. 不動点。下段は再マージで残る（INV-13）。再保存・開き直しで増えない・二重にならない。

## 3. 下段の中身と解決

- 下段のデータは既存の `templatePendingDesks["<cellId>::<deskId>"] = { lower, effectiveStartDate, createdAt }`（`templatePendingDesks.ts`）。
  `lower.lesson.studentSlots` に押し出された生徒を入れる。`effectiveStartDate` はその日付（丸ごと振替・休日解除は操作日の対象日、Q40-2・追従はテンプレの反映日）。
- **理由を持たせる**: `TemplatePendingDesk` に任意項目 `origin?: { kind: 'whole-day-transfer-displaced' | 'transfer-follow-full' | 'holiday-release-seat-taken' | 'slot-follow-full'; note: string }` を足す
  （旧データは無し＝従来のテンプレ保留）。ツールチップと保留の帯・一覧に理由文を出す。色は緑のまま。
- **解決**: 既存の 3 通り。(1) 室長が下段の生徒を別の机・別の日へ動かす（下段が空けば 1 行に戻る）。(2) 「既存を採用」「テンプレを採用」（既存の意味どおり。
  「テンプレを採用」は下段を捨てる＝在庫由来は未消化へ・手動追加は消える。室長の明示操作）。(3) **上段の席が空いたら自動で 1 行に戻す（Q28・決定 A）**。
  Q28 の発火点がテンプレ保存だけなら、開き直し（再マージ）でも戻すかを実装時に確認して決める（オーナーの意向は「効かせる」）。
- **件数と一覧**: テンプレ保存の確認の画面と保存後の 1 行の「保留 n机」に含める。丸ごと振替・休日解除の確認ダイアログに「保留に残す授業: n 件」と名前。
  盤面上部の保留の帯（既存）に、週をまたいだ一覧が無ければ「保留 n 件」のバッジ＋一覧（日付・時限・生徒・理由・そのコマへ移動）を足す（棚卸しの共通の弱点「保存後に誰がどこへ行ったか追えない」への手当て）。
