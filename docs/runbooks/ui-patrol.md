# Runbook: 画面の自動巡回(`tools/ui-patrol.mjs`)

本番の形のデータ(名前は伏せる)を手元のアプリに入れ、室長と同じ画面操作を自動で行い、操作のたびに
「変なことが起きていないか」を点検する。設計と決定の記録は `docs/test-strategy.md` の「画面の自動巡回(層 5)」。

> ⚠️ **守ること**
> - 本番は**読むだけ**(バックアップの GET と、最新の時点を引く `:runQuery`)。書き込み・復元・Cloud Functions の呼び出しはしない。
> - 出力先(`--out`)は**スクラッチ領域**にする。リポジトリの中は道具が断る。画面写真・種データをリポジトリ・Issue・公開の場へ出さない。
> - 報告に出るのは仮名(生徒092・講師005)と ID だけ。実名は道具がファイルに書かない。

## 1. いつ回すか

- **盤面のロジックや画面を変えた修正を main へ入れる前**に、Claude が回す(`safe-release` のチェックリスト)。
  - 目安: `src/components/schedule-board/`・`src/App.tsx`・`src/data/`・テンプレ・保存・読み込みに触れた変更。
  - 文言だけ・文書だけ・`functions/` だけの変更では回さなくてよい。
- 毎朝の健診には入れない(オーナー決定 2026-11-11)。毎晩の自動実行は第 2 段の案。

## 2. 回し方

```bash
npm ci --no-audit --no-fund          # node_modules が無ければ
S=<スクラッチ領域>/ui-patrol-$(date +%Y%m%d-%H%M)
node tools/ui-patrol.mjs --out "$S"
echo "終了コード: $?"
```

- 読み取り専用トークンは、環境変数 `KOMAHYOU_READONLY_SA_JSON_B64` から道具が自分で作る(`FIRESTORE_ACCESS_TOKEN` があればそれを使う)。
- Playwright と Chromium は Claude のクラウド環境に入っている(入れ直さない)。無い環境では終了コード 2 で止まる。
- 開発用サーバー(ローカルモード・ポート 5199)は道具が起動して、終わったら止める。

よく使う引数:

| 引数 | 意味 |
|---|---|
| `--out <dir>` | 出力先(必須・リポジトリの外)。報告・画面写真・伏せ字の種データを置く |
| `--classroom <id>` | 教室を絞る(複数可)。既定は本番 2 校 |
| `--key <YYYY-MM-DDTHH-mm>` | 過去の時点のバックアップで流す(既定は最新)。JST の時刻 |
| `--scenario boot,c,b,a` | 台本を絞る(`boot` は必ず流れる) |
| `--moves <n>`・`--seed <n>` | 生徒の移動の数(既定 6)と、選び方の種(既定 1) |
| `--random <n>` | でたらめ操作を n 手(試験的・既定 0＝流さない)。台本 b のあと・a の前に流れる |
| `--prepare-only` | 取得・伏せ字・自己点検だけ(ブラウザは開かない) |
| `--seed-file <path>` | 前に作った伏せ字の種データ(`<out>/<教室ID>.seed.json`)で流し直す(取得しない)。`--classroom` と同じ数・同じ順 |
| `--headed` | ブラウザを画面に出す(手元の PC で動きを見たいとき) |

所要時間の目安(2026-11-11・本番 2 校・全部の台本): **約 3 分半**。1 校・台本 a だけなら約 25 秒。

## 3. 終了コードと報告の読み方

| 終了コード | 意味 | すること |
|---|---|---|
| 0 | 「変」なし | そのまま進む |
| 1 | 「変」(止める所見)あり | **マージを止めて調べる**(§4) |
| 2 | 流せなかった・途中で止まった・何も操作できなかった | 環境か台本の問題。報告の `[中断]` の理由と画面写真を見る(§5) |
| 130 | Ctrl+C などで止めた | ブラウザとサーバーは片づく。報告は書かれない |

報告は標準出力と `<out>/report.txt`・`<out>/report.json`。`[変]` が止める所見、`[知]` が知らせるだけの所見。
`[変]` が出た手順の画面写真は `<out>/<教室ID>-<台本>-<連番>.png`、そのコマの前後の机の中身(仮名と ID だけ)は同じ名前の `.diff.json`。

報告の 1 行目に「操作 n 回」が出る。**操作が少なすぎないか**も見る(台本 b の移動は 1 か所あたり 4 回＝移動・元に戻す・やり直し・元に戻す)。
移動の候補が来週に無いときは、その先の 3 週まで順に探す。4 週とも無い・移動が 1 回も効かないときは中断(終了コード 2)になる。

## 4. 「変」が出たとき

1. 報告の 1 件 1 行(日付・時限・机・仮名・生徒 ID)と画面写真で、何が起きたかを見る。
2. **自分の変更が原因か**を切り分ける: 変更前のコミット(`git stash` か `git switch --detach origin/main`)で、同じ種データ
   (`--seed-file <out>/<教室ID>.seed.json`)を流す。変更前は出ず、変更後だけ出るなら自分の変更が原因。
3. 自分の変更が原因 → 直す。回帰防止テスト(ユニット)も足す(巡回はユニットの代わりではない)。
4. 変更前から出る → 本番のデータに今ある状態で起きる不具合の疑い。直さずにオーナーへ報告する(場所・手順・画面写真)。
5. 仕様どおりの動きを点検が取り違えている(誤報)→ 根拠(仕様の節・コードの関数)を確かめたうえで、
   `tools/ui-patrol-known.json` に ID だけ・理由つきで載せるか、点検を直す。**緑にするためだけに点検を緩めない。**

`tools/ui-patrol-known.json` の 1 件の形(書いた項目がすべて一致する所見だけ外す):

```json
{ "code": "manual-student-teacher-changed", "classroomId": "<教室ID>", "step": "a", "dateKey": "2026-11-19", "slotNumber": 3, "studentId": "s0xx", "note": "理由と確かめた根拠" }
```

## 5. 途中で止まったとき(終了コード 2)

| 出た文 | 原因 | すること |
|---|---|---|
| 読み取り専用トークンを作れません | 環境変数が無い | トークンのある環境で回す。無ければ `--seed-file` で前の種データを使う |
| 教室別の形ではない／HTTP 4xx | バックアップの時点が無い・形が違う | `--key` を見直す |
| 伏せ字のあとに名前が残っています | 名前の入る新しい項目が増えた | `tools/ui-patrol/anonymize.ts` の一覧に足す(経路が出る) |
| 保証台帳の結果が伏せ字の前後で違います | 伏せ字で挙動が変わった | 名前の対応の規則を見直す |
| 待ちが時間切れ・testid が見つからない | 画面が変わった | `tools/ui-patrol/selectors.mjs` と台本を画面に合わせる(ユニット `selectors.test.mjs` が先に落ちるはず) |
| 移動しても何も起きませんでした | 長押しドラッグが効いていない(画面の作りが変わった・席が画面の外) | 画面写真を見る。`tools/ui-patrol/driver.mjs` の `dragStudent` を画面に合わせる |
| 効いた移動が 1 回もありません | 4 週とも候補が無い・全部アプリに断られた | 休みの続く時期かを確かめる。`--scenario boot,c,a` で残りを流す |
| ポートが使用中 | 前の巡回や別の開発用サーバーが残っている | `--port` を変えるか、残ったプロセスを止める |
| Playwright が無い | 環境 | Claude のクラウド環境で回す |

## 8. 限界

- 実 Firebase の保存・復元・QR 提出・Cloud Functions は通らない。
- 台本に無い操作の不具合は見つからない。
- 伏せ字は名前の「一致」を保つが、名前の一部を切り出す処理の結果までは保てない(自己点検が番人)。

## 9. いま出る所見(2026-11-11 時点・アプリの修正待ち)

巡回を初めて本番の形で流したところ、今のコード(v1.5.717)で次の 2 つの形が止まった。どちらもテンプレ保存(台本 a)で、
**先の反映日のテンプレが保存済みの教室で、反映日を手前へ動かして保存したとき**に出る。`tools/ui-patrol-known.json` には載せていない(隠さない)。

| 形 | 何が起きるか | いま出る教室 | 扱い |
|---|---|---|---|
| A | 別の講師の授業に手で入れた講師の机で、テンプレも同じ講師をその机に置くのに、保存で講師だけが空き机へ移り、テンプレの生徒が講師なしで残る。確認の画面に出ない | 日大前校(29 机・11/17〜1/28 の火・木・月の 3 限) | アプリの不具合の疑い。直すまで止まる |
| B | 室長が講師を消した机(削除記録)へ、テンプレの生徒が講師なしで置かれる(同じ日の中で別の講師へ動かしていた生徒が戻る・全部消した日に新しいテンプレの生徒が現れる) | 日大前校(10 机)・緑が丘校の 11/10 朝の形(9 件) | 仕様の穴。オーナーが決める |

直るまでの回し方: 日大前校の台本 a は終了コード 1 になる。自分の変更の前後で、同じ種データ(`--seed-file`)の所見の件数と場所を比べ、
**増えていなければ**進む(比べた結果をコミットか報告に書く)。A・B が直ったら、この節を消す。
