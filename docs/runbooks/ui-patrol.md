# Runbook: 画面の自動巡回(`tools/ui-patrol.mjs`)

本番の形のデータ(名前は伏せる)を手元のアプリに入れ、室長と同じ画面操作を自動で行い、操作のたびに
「変なことが起きていないか」を点検する。設計と決定の記録は `docs/test-strategy.md` の「画面の自動巡回(層 5)」。

> ⚠️ **守ること**
> - 本番は**読むだけ**(バックアップの GET と、最新の時点を引く `:runQuery`)。書き込み・復元・Cloud Functions の呼び出しはしない。
> - 出力先(`--out`)は**スクラッチ領域**にする。リポジトリの中は道具が断る。画面写真・種データをリポジトリ・Issue・公開の場へ出さない。
> - 報告に出るのは仮名(生徒092・講師005)と ID だけ。実名は道具がファイルに書かない。
>   - 但し書き: 名簿から消した生徒の古い内部の鍵のように「盤面にも名簿にも出ない名前」が鍵の中にあると、伏せ字も漏れ検査も掛からず、
>     種データ(スクラッチ領域)に残ることがある(報告と画面写真には出ない)。2026-11-11 の本番 2 校には該当なし。だから種データもスクラッチ領域の外へ出さない。

## 1. いつ回すか

- **盤面のロジックや画面を変えた修正を main へ入れる前**に、Claude が回す(`safe-release` のチェックリスト)。
  - 目安: `src/components/schedule-board/`・`src/App.tsx`・`src/data/`・テンプレ・保存・読み込みに触れた変更。
  - 文言だけ・文書だけ・`functions/` だけの変更では回さなくてよい。
- 毎朝の健診には入れない(オーナー決定 2026-11-11)。毎晩の自動実行はやらない(オーナー決定 2026-11-11)。
- **テンプレ・再反映・保存/読み込みを触った変更**では、いつもの巡回に加えて `--incidents`(過去の事故の日の形・§6)も流す。既定では流れない(既定は最新のデータだけ・約 10 分のまま=2026-11-11 オーナー決定)。

## 2. 回し方

```bash
npm ci --no-audit --no-fund          # node_modules が無ければ
S=<スクラッチ領域>/ui-patrol-$(date +%Y%m%d-%H%M)
node tools/ui-patrol.mjs --out "$S"
echo "終了コード: $?"
```

- 読み取り専用トークンは、環境変数 `KOMAHYOU_READONLY_SA_JSON_B64` から道具が自分で作る(`FIRESTORE_ACCESS_TOKEN` があればそれを使う)。
- Playwright と Chromium は Claude のクラウド環境に入っている(入れ直さない)。無い環境では終了コード 2 で止まる。
- 開発用サーバー(ローカルモード・ポート 5199)は道具が起動して、終わったら止める。

よく使う引数:

| 引数 | 意味 |
|---|---|
| `--out <dir>` | 出力先(必須・リポジトリの外)。報告・画面写真・伏せ字の種データを置く |
| `--classroom <id>` | 教室を絞る(複数可)。既定は本番 2 校 |
| `--key <YYYY-MM-DDTHH-mm>` | 過去の時点のバックアップで流す(既定は最新)。JST の時刻 |
| `--scenario boot,c,b,e,f,a,d` | 台本を絞る(`boot` は必ず流れる)。流れる順は 起動 → c → b → (でたらめ操作) → e → f → a → d → g → h で、指定の順ではない。**台本 g と h は既定では流れない**(下の表)。g は休日設定・丸ごと振替・在庫の会計を触った変更のときに足す(例 `--scenario c,b,e,f,a,d,g`)。h は講習の自動割振や在庫の会計を触った変更のときに足す(例 `--scenario c,b,e,f,a,d,h`。割り振れる未消化講習が無い時期は終了コード 2・下の注) |
| `--moves <n>`・`--seed <n>` | 生徒の移動の数(既定 6)と、選び方の種(既定 1)。種は台本 e の生徒・振替先、台本 f のコマ・机・講師、台本 d の机・生徒・講師、台本 g の日付、台本 h の生徒の選び方にも効く |
| `--random <n>` | でたらめ操作を n 手(試験的・既定 0＝流さない)。台本 b のあと・a の前に流れる |
| `--prepare-only` | 取得・伏せ字・自己点検だけ(ブラウザは開かない) |
| `--seed-file <path>` | 前に作った伏せ字の種データ(`<out>/<教室ID>.seed.json`)で流し直す(取得しない)。`--classroom` と同じ数・同じ順 |
| `--headed` | ブラウザを画面に出す(手元の PC で動きを見たいとき) |
| `--baseline-ref <git の ref>` | **変更前のコードと自動で比べる**(§4)。その ref のアプリで同じ台本を先に流し、今の作業ツリーの結果と比べて「変」を 新しい／前から／消えた に分ける。例 `--baseline-ref origin/main` |
| `--baseline <report.json>` | 前に流した報告(`<out>/report.json`)と比べる。同じ種データ(`--seed-file`)で流したものどうしだけ。**台本・移動の数・乱数の種・でたらめの数・今日の日付・データの時点・教室が違う報告は断る**(報告の `conditions` で突き合わせる。条件の記録が無い古い報告〔v1.5.730 までの道具〕も断る=同じ引数で取り直す)。`--baseline-ref` は同じ条件で 2 回流すので影響なし |
| `--incidents [<名前,名前>]` | **過去の事故の日の形**を順に流す(§6)。一覧は `tools/ui-patrol-incidents.json`。名前を省くと全部。件ごとにその時点・教室・台本で流し、出力は `<out>/<名前>/`・まとめは `<out>/incidents.txt`。`--baseline-ref` と一緒に使える。`--key`・`--seed-file`・`--classroom`・`--scenario`・`--baseline`・`--json` とは一緒に指定できない |

台本(教室ごとにこの順で流れる。操作は室長と同じ画面操作。設計は `docs/test-strategy.md` 層 5):

| 台本 | すること | 変わってよい範囲 |
|---|---|---|
| boot | 伏せ字のデータを入れて開く | 開いたときの再反映(テンプレ由来)。手入力は変わってはいけない |
| c | 保存 → 読み込み直し | なし |
| b | 生徒の長押しドラッグ → 元に戻す → やり直し → 元に戻す(6 か所) | 動かした元と先の机だけ |
| e | 出欠。生徒メニューで 通常の休み(元に戻す → やり直し も確かめる)→ その休みで増えた振替を未消化振替の一覧から別のコマの空いた席へ置く → 通常の振無休 → 通常の出席 → 振替の休み → 講習の出席。最後に 保存 → 読み込み直し | 操作した席の机(机の中でも操作した席とその生徒の記録 1 件だけ)と、振替の台帳・抑止キー。加えて、在庫の増減が仕様どおり(休み +1・振無休 ±0・出席 ±0・振替先へ置く −1・ほかの生徒と講習は ±0・数えるのはアプリの関数)・記録が付いた・振替先に座った・元に戻すで盤面と在庫が前と同じ、を見る |
| f | 講師。講師欄の長押しドラッグで 講師の移動(同じコマの講師の居ない机へ)→ 講師だけ入替 → 生徒ごと席入替(生徒のいる机へ落とすと出る選ぶ画面)→ 講師メニューで講師を替える(そのコマに居ない講師へ)→ 休みの流れ(講師 X を「休み」→ その机に代わりの講師 Y → X を同じコマの空き机へ講師メニューで置く → 元に戻す 1 回)→ 休み → 同じボタンで解除。最後に 保存 → 読み込み直し | 操作した机(移動・入れ替えは 2 机)の講師の欄。生徒ごと席入替はその 2 机の中身の入れ替わり。休みの講師を置いたときは同じコマで休みの記録だけ消えた机。加えて、机ごとに仕様の形(講師・入った講師は手入力・休みの記録・中身が残る/入れ替わる)・そのコマに X の休みの記録が残らない・元に戻すで X の配置と記録が戻る・在庫は全部 ±0、を見る |
| a | テンプレ編集を開く → 反映日を来週の月曜 → 何も変えずに保存 → 保存 → 読み込み直し | 反映日以降のテンプレ由来の部分。台本 e が付けた出欠記録のコマに生徒を置き直したら「変」(§2-4 記録が勝つ・d も同じ) |
| d | テンプレを実際に変えて保存。1 回の保存に 1 種類ずつ: 生徒を 1 人足す(空いた席へ名簿の生徒)→ 講師を替える(そのコマに居ない講師へ)→ 机を消す(机の生徒と講師)。最後に 保存 → 読み込み直し | a と同じ。加えて、変えた机で起きるはずの変化(足した生徒が居る・替えた講師が居る・消した机の生徒と講師がテンプレのまま残らない)と、保存したテンプレにその変更が入っていることを見る |
| g(**既定では流れない**) | 休日設定と解除・丸ごと振替(作成と解除)。来週から 4 週を開いて日付を選ぶ。日付の見出しのメニュー「休日設定」(元に戻す → やり直し も確かめる)→ 保存 → 読み込み直し → 休日の見出しを押して解除。メニュー「丸ごと振替」→ 同じ曜日の振替先の見出し(断られたら次の候補)→ 保存 → 読み込み直し → メニュー「丸ごと振替を解除」。最後に 保存 → 読み込み直し。作ったものは解除して元へ戻すので最後に流す | 操作した日(休日にした日／振替元・振替先の日)の机と、休日は教室設定(休日の日付)と在庫の台帳、解除は抑止キーも、丸ごと振替は抑止キー(組の鍵)。加えて、休日はその日の席が空き「休)」が付く・在庫が仕様どおり(通常・振替の生徒 1 人につき未消化振替 +1・数え方が別の生徒の鍵と講習は比べない・ほかは ±0)、丸ごと振替は振替先の同じ時限・机・席に振替元の生徒と講師が乗り振替元に「休)」・在庫は全部 ±0、解除のあとは作る前の盤面・部分・在庫と全部同じ、を見る |
| h(**既定では流れない**) | 講習の自動割振。ツールバー「未消化講習」→ 生徒の行 →「自動割振」。1 回目は講習だけ、2 回目は「未消化振替も同時に自動割り当てする」を入れて別の生徒。押す前に講習の期間の週を全部開く。1 回ごとに 押す → もう一度押す(何も変わらない)→ 保存 → 元に戻す → 保存 → やり直し。最後に 保存 → 読み込み直し | 講習の期間の机のうち、前は空いていた席にその生徒の講習(振替も同時に、なら振替も)が座ることだけ。部分は講習の在庫の台帳(`manualLectureStockCounts`・`manualLectureStockOrigins`)だけ。加えて、置いた席が期間の中・講師のいた机・開いているコマ・そのコマに 1 席・出席不可のコマでない・制約事項(指定時限禁止・科目対応講師のみ)に反しない、在庫が置いた数だけ減る(その行の未消化講習 −講習の数・未消化振替 −振替の数・ほかは ±0)、画面の文の件数＝置いた席の数、2 回目は盤面も在庫も変えない(INV-03)、元に戻すで押す前と全部同じ、を見る |

## 3. 終了コードと報告の読み方

| 終了コード | 意味 | すること |
|---|---|---|
| 0 | 「変」なし | そのまま進む |
| 1 | 「変」(止める所見)あり | **マージを止めて調べる**(§4) |
| 2 | 流せなかった・途中で止まった・何も操作できなかった | 環境か台本の問題。報告の `[中断]` の理由と画面写真を見る(§5) |
| 130 | Ctrl+C などで止めた | ブラウザとサーバーは片づく。報告は書かれない |

報告は標準出力と `<out>/report.txt`・`<out>/report.json`。`[変]` が止める所見、`[知]` が知らせるだけの所見。

`--incidents` のときは件ごとに `<out>/<名前>/report.txt`(1 行目に `[事故の日の形 <名前>・時点 <key>]`・2 行目に何の事故の形か)と、全体のまとめ `<out>/incidents.txt`・`incidents.json`(件ごとの終了コードと 1 行目)。
全体の終了コードは、どれかの件に「変」(1)があれば 1(流せなかった件があっても 1。「変」を 2 に隠さない)、変が無くどれかの件が流せなければ 2、全部変なしで 0。件の中の決まり(中断は 2 が先など)は 1 回の巡回と同じ。
変を出したあと途中で止まった件(件の終了コード 2・報告に変がある〔`--baseline-ref` のときは新しい変〕)も全体では 1 に数え、まとめに「途中で止まる前に変 n 件」と出す。
途中で止める(Ctrl+C など)と `incidents.txt`・`incidents.json` は書かれない(止めた件の報告も書かれない・それまでに済んだ件の `<out>/<名前>/report.txt` は残る)。`--baseline-ref` と一緒のときは件ごとに変更前のアプリの取り出しからやり直すので、件の数だけ時間がかかる。

`--baseline-ref`／`--baseline` を付けたときは、止める所見を 3 つに分けて出す。**終了コードは「新しい変」があるかで決まる**
(新しい変が 1 件でもあれば 1。新しい変が 0 なら、前からの変が残っていても 0。2 と 130 の条件は同じ)。

| 印 | 意味 |
|---|---|
| `[変・新]` | 変更前には無く、今回だけ出た(自分の変更が原因) |
| `[変・前]` | 変更前から出ている(自分の変更が原因ではない) |
| `[消えた]` | 変更前には出ていて、今回は出ない(自分の変更で直った) |

1 行目は `変 n 件(新しい a・前から b)・消えた変 c 件・知らせるだけ m 件・操作 k 回` の形になる。
`[変]` が出た手順の画面写真は `<out>/<教室ID>-<台本>-<連番>.png`、そのコマの前後の机の中身(仮名と ID だけ)は同じ名前の `.diff.json`。

報告の 1 行目に「操作 n 回」が出る。**操作が少なすぎないか**も見る(台本 b の移動は 1 か所あたり 4 回＝移動・元に戻す・やり直し・元に戻す。台本 d は 1 回の保存あたり 5 回＝開く・反映日・机を変える・保存・確認。台本 e は 1 つあたり 1 回、最初の休みだけ 3 回＝押す・元に戻す・やり直し。台本 f は 1 つあたり 1 回、休みの流れの 3 手目と休みと解除は 3 回〔保存を押せたとき〕、最後の保存→読み込み直しは 1〜2 回。台本 g は 休日設定が 3〜5 回〔押す・保存・元に戻す・保存・やり直し〕・解除 1 回・丸ごと振替 2 回〔メニュー・振替先〕・解除 1 回・保存→読み込み直しが 1〜2 回ずつ。台本 h は 1 回あたり 3〜6 回〔押す・2 回目〔行が残っているときだけ〕・保存・元に戻す・保存・やり直し〕と最後の保存→読み込み直し 1〜2 回)。
移動の候補が来週に無いときは、その先の 3 週まで順に探す。4 週とも無い・移動が 1 回も効かないときは中断(終了コード 2)になる。

## 4. 「変」が出たとき

1. 報告の 1 件 1 行(日付・時限・机・仮名・生徒 ID)と画面写真で、何が起きたかを見る。
2. **自分の変更が原因か**を道具に分けさせる。同じ種データで、変更前のコードと比べて流し直す:

   ```bash
   node tools/ui-patrol.mjs --out "$S-b" --baseline-ref origin/main \
     --classroom <教室ID> --seed-file "$S/<教室ID>.seed.json"
   ```

   - 道具が `origin/main` のアプリを `<out>/baseline-app/` に取り出して先に流し(結果は `<out>/baseline/`)、続けて今の作業ツリーで流して比べる。
     **作業ツリー・ブランチには触らない**(`git stash` や切り替えは要らない。手で戻す手順は戻し忘れの元なので使わない)。
   - 比べる相手は、変更を入れる前のコミットにする(作業ブランチなら `origin/main`、main の上で直しているなら直す前のコミット)。
   - 断られるとき(終了コード 2): 依存(`package-lock.json`)が変更前と違う／変更前が読み口の無い版(v1.5.718 より前)／ref が無い。
     そのときは、前に流した報告があれば `--baseline <report.json>` で比べる。
3. `[変・新]` が出た → 自分の変更が原因。直す。回帰防止テスト(ユニット)も足す(巡回はユニットの代わりではない)。
4. `[変・前]` だけ → 本番のデータに今ある状態で起きる不具合の疑い。終了コードは 0 なのでマージは止めないが、**直さずにオーナーへ報告する**(場所・手順・画面写真)。
5. 仕様どおりの動きを点検が取り違えている(誤報)→ 根拠(仕様の節・コードの関数)を確かめたうえで、
   `tools/ui-patrol-known.json` に ID だけ・理由つきで載せるか、点検を直す。**緑にするためだけに点検を緩めない。**

`--baseline-ref` の注意:
- 2 つ同時には流せない(開発用サーバーのポートと `node_modules` を共用する)。`tar` コマンドを使う。
- 変更前のアプリも、今の作業ツリーと同じ設定で動かす(追跡されていない `.env.local` などを取り出し先へ複製する)。ローカルモードと
  localhost 以外への通信止めは 2 回とも同じに効く。取り出し先(`<out>/baseline-app/`)は終わると消える。
- `--baseline <report.json>` は、台本・移動の数・乱数の種・でたらめの数・今日の日付・データの時点が同じ報告どうしで使う。違えば道具が断る(終了コード 2・何が違うかを出す)。データの時点は両方が本物の時点のときだけ比べる(`--seed-file` で流した側は `seed-file`。同じデータかは種データの指紋が見る)。
- 変更前の巡回の最中に止めると(Ctrl+C の 2 回目・強制終了など片づけが走らなかったとき)、取り出し先 `<out>/baseline-app/` がスクラッチ領域に残ることがある。同じ `--out` で次に `--baseline-ref` を流すと、取り出しの前に前回の残りを消す(`baselineApp.mjs` の始めの片づけ)。別の `--out` に変えたときは手で消す。
- 突き合わせは 2 段(2026-11-11)。1 段目は手順の題名(と、題名まで同じ手順の何本目か)まで同じ所見どうし。残ったものを 2 段目で「台本の記号＋所見の種類・日付・時限・机・生徒・文」だけで組にし、`[変・前・別の手順]` と出す(新しい変に数えない)。
  題名には候補の通し番号と種類(「生徒の移動 N(種類)」「講師 N(…)」)が入るので、変更前と今で候補の数・順がずれても、同じ場所の同じ所見を「新しい」と誤らないため。別の机・別の文は 2 段目でも組にならず「新しい」のまま。

`tools/ui-patrol-known.json` の 1 件の形(書いた項目がすべて一致する所見だけ外す):

```json
{ "code": "manual-student-teacher-changed", "classroomId": "<教室ID>", "step": "a", "dateKey": "2026-11-19", "slotNumber": 3, "studentId": "s0xx", "note": "理由と確かめた根拠" }
```

## 6. 過去の時点で流す(事故の形を見張る)

バックアップは 15 分ごと(24 時間)→ 毎時相当(72 時間)→ 日次(JST 3:00・400 日)で残る。決まった時点を長く残すなら日次の時点(`…T03-00`)を使う。

1 つの時点だけなら `--key`:

```bash
node tools/ui-patrol.mjs --out "$S" --classroom KzFnOQoTFLsCxwUp1tvh --key 2026-11-10T03-00 --scenario a
```

**決まった一覧で流す(`--incidents`・2026-11-11 第 2 段の順 2)**: 過去の事故の日の形を `tools/ui-patrol-incidents.json` に持ち、1 つの引数で順に流す。

```bash
node tools/ui-patrol.mjs --out "$S" --incidents                       # 一覧の全部
node tools/ui-patrol.mjs --out "$S" --incidents nichidaimae-2026-11-11-teacher-detached   # 選んだものだけ(カンマ区切りで複数)
node tools/ui-patrol.mjs --out "$S" --incidents --baseline-ref origin/main   # 件ごとに変更前のアプリと比べる
```

## 8. 限界

- 実 Firebase の保存・復元・QR 提出・Cloud Functions は通らない。
- 台本に無い操作の不具合は見つからない。
- 伏せ字は名前の「一致」を保つが、名前の一部を切り出す処理の結果までは保てない(自己点検が番人)。
- 台本 h: 講習の講師を自動で置く経路(講師日程表の登録・QR 提出の反映)は通らない。全員まとめての自動割振の入口は無い。制約事項の「通常講師のみ」・1 日のコマ数の上限・講師欄が名前だけの机の
  「科目対応講師のみ」は確かめない(アプリの判定が画面の中の関数で、道具から呼べない)。講習の提出の前の時期は候補が無く流せない(h だけなら終了コード 2・既定＋h なら飛ばすだけ)。
- 変更前との比較の鍵は「教室・手順(台本・題名・何本目か)・所見の種類・日付・時限・机・生徒 ID・文」。「ほか n 机」にまとめた所見は件数が同じまま中身が入れ替わっても気づけない(第 2 段の残りで直す候補)。
- `--incidents`: 件に流す日(`today`)を書けば、道具の今日とアプリの時計をその日にするので、日が進んでも同じ日の操作になる(書かない件は実際の今日で流れ、日が進むほど事故の形を通らなくなる)。
  止めるのは画面の中の時計(Date・タイマー)だけで、開発用サーバーや道具の側の時刻(報告の所要時間など)は本物のまま。一覧の件は、道具やアプリを大きく変えたら修正前のアプリで「変」が出るかを確かめ直す(§6)。
