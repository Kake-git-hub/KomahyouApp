# Runbook: 室長から「生徒の授業がおかしい」と連絡を受けたときの調べ方(読み取り専用)

室長の連絡はたいてい曖昧(「未消化が多分消えてる」「組んだ通りになってない」)。1 週間以上前の話のこともある。
この手順で **その生徒に何が起きたか** を記録から並べ、室長に「何が起きたか」と「どこを押せば直るか」を返す。
作った経緯: `docs/plan-2026-11-09-student-tracing-and-inv-audit.md`(2026-11-09 オーナー確定)。

> ⚠️ **やってはいけないこと**: 本番(`komahyouapp-prod`)の Firestore / Storage への書き込み・復元・コピー・Cloud Functions の呼び出し。
> 調べるのは**読むだけ**。直すのは室長が画面で行う(必要ならオーナーが判断する)。書き込みを伴う確かめは開発用教室 `v8OZ7zH8vONNHjjYVcR1` で。
> 生徒・講師の名前は Issue・コミット・公開の記録に書かない(生徒は ID、例 `s072`)。

## 1. 連絡の受け方(4 つを聞く)

| 聞くこと | 例 | なぜ |
|---|---|---|
| 教室 | 緑が丘校 | 教室 ID を決める(CLAUDE.md の教室一覧) |
| 生徒 | 生徒 ID か、名前 → 名簿で ID に直す | ツールは ID で引く |
| いつ頃 | 「先週の火曜くらい」「11 月に入ってから」 | 期間 `--from` を決める。迷ったら広めに(2 週間) |
| 何が | 未消化が減った/増えた・コマが消えた・別のコマに移った・出欠が変わった | 時系列のどの行を見るか決める |

- 名前から生徒 ID を引くには、アプリの基本データ画面(生徒の一覧)で生徒 ID を見るか、室長に生徒 ID を聞く。名前をツールや Issue に渡さない。

聞き取れなかった点は推測で埋めず、室長に聞き返す。

## 2. 生徒ごとの経緯を出す(`tools/student-timeline.mjs`)

```bash
export FIRESTORE_ACCESS_TOKEN=$(node tools/prod-readonly-token.mjs)   # 読み取り専用・1 時間有効
node tools/student-timeline.mjs --workspace main --classroom <教室ID> --student <sNNN> --from YYYY-MM-DD [--to YYYY-MM-DD]
```

- 4 つの記録を、その生徒の分だけ時刻順(JST)に 1 本で出す。
  - **[台帳]** 生徒授業台帳。科目ごとの未消化振替・未消化講習・出席/休み/振無休/配置。**前の台帳の日から変わった日(変化日)** に「何がいくつからいくつへ」「消えた元コマ」を出す。
  - **[操作ログ]** 在庫が減る・記録が消える操作(未消化の × 削除・コマの削除・出欠・休日・丸ごと振替・自動処理)。休日などの日付全体の操作は、その生徒の授業がある日のものだけ出す。
  - **[痕跡]** 保存に同梱された盤面の確定の要約(2026-10-22 から)。
  - **[版]** 変化日の最初と最後の保存の版と、その直前の版(前の台帳日の最後の保存)を比べた**その生徒の机の変化**(全部の版は落とさない)。
    盤面の生徒に名簿の ID が付いていない机・痕跡は名前で拾い、「(名前で一致)」と印を付ける。出欠で上書きされた側の生徒の操作ログには「(上書きされた側)」が付く。
- 名前は既定で ID に置き換わる(他の生徒・講師も)。名前で読みたいときだけ `--show-names` を付け、**出力はスクラッチ領域にだけ置く**(Issue・コミットに貼らない)。
- 「この日の保存の版は無い」= その日は保存されていない(版履歴が無い)。「取得できず: 理由」= その記録が読めなかった(トークン切れ・保持期間切れなど)。空の結果を「何も起きていない」と取り違えない。
- 記録がある期間: 台帳と操作ログは 2026-09-04 から、痕跡は 2026-10-22 から、版は直近 90 日。これより前は出ない(ツールが注意を出す)。
- `--json` で同じ内容を JSON で出す(他のツールへ渡す用)。

### 出力の扱い

- 名前は「名前#ID」の形と名簿の名前(前後が文字の途中でないもの)だけを伏せる。名簿に無い人(体験生・名簿外)は「体験生#エントリID」「名簿外#エントリID」になる。
- **メモなどの自由記述に書かれた名前や、名前に続けて書かれた文(「〇〇の」など)は伏せられないことがある。** 出力はスクラッチ領域にだけ置き、Issue・コミット・公開の場へ貼らない。

### 読み方の目安

| 室長の言い方 | 見るところ |
|---|---|
| 未消化が消えた/減った | [台帳] の「未消化振替 n→m」「未消化の元コマ -日付#限」の直前にある [操作ログ](× 削除・未消化へ戻す・出欠)と [版](その元コマの振替が置かれた・消えた机) |
| 組んだ通りになっていない | [版] の机の前後(誰がどのコマから消え、どこに入ったか)と、同じ時刻の [痕跡](人の操作か)。人の操作の痕跡が無いのに机が変わっていれば自動処理を疑う。v1.5.714 からは自動処理が机を変えると [痕跡] に「自動: <処理名>: <机の差>」の行が出る(盤面を開いたときの再反映・基本データ変更時の再反映・起動時の自己修復・QR 提出の反映) |
| 出欠が変わった | [操作ログ] の出欠を付けた/外した と [版] の `[休み …]` などの記録 |

## 3. 必要なら保証台帳の違反を洗い出す(`tools/inv-audit.mjs`)

経緯で**バグらしい**(人が操作していないのに変わった・同じコマに同じ生徒が 2 か所・休日に授業が残る など)と分かったら、
同じ形の被害がほかの生徒にも出ていないかを、教室データ全体から洗い出す。

```bash
# 教室ファイル(教室別バックアップ・版履歴など)をスクラッチ領域に落としてから(落とし方は morning-health-check.md §1〜2)
node tools/inv-audit.mjs "<スクラッチ領域>/<教室ファイル>.json.gz" --classroom <教室ID> --known tools/board-health-known-issues.json
```

- 物差しは `docs/spec-invariants.md` の保証文(「決めつけずに保証台帳に違反しているものがバグ」)。出力は生徒 ID だけ。
- 見つかった生徒それぞれに 2 の経緯ツールを当て、いつ・何で崩れたかを確かめる。
- バグと分かったら修正の流れ(triage → dev-fix)へ渡す。利用者報告 Issue(`source:user-report`)はオーナーの許可が出るまで修正に入らない。

## 4. 室長への返事

平易な言葉で、次の 3 つを短く書く(社内の記号・関数名・INV 番号は書かない)。

1. **何が起きたか**: 「11 月 4 日の午後の保存で、5 日 4 限の数学が別の生徒に置き換わり、元の振替の元コマ(2 日 3 限)が未消化から消えていました」のように、日時・コマ・前後。
2. **なぜか**(分かる範囲で): 「× で削除された記録があります」「その時刻に手の操作の記録は無く、自動の処理で変わったようです(調べています)」。分からないことは分からないと書く。
3. **どこを押せば直るか**: 例「未消化振替の一覧で〇〇を追加し直してください」「盤面の 5 日 4 限を開いて、生徒を元のコマへ戻して保存してください」。
   画面で直せないもの(データの戻しが要るもの)は、室長に触らせずオーナーへ上げる(戻しは `docs/runbooks/rollback.md`・本番データの戻しはオーナー判断)。

返事やメモに生徒の名前を書くかは室長とのやり取り(私的な経路)に限る。Issue・コミットには ID だけを書く。
