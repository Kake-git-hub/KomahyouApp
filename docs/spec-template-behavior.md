## A. 反映日（effectiveStartDate）の境界

**Q1.** ✅ 確定。テンプレ反映日**より前**のコマ表は、テンプレ反映で**一切変更しない**（講師・生徒・出欠・メモすべて不変）。再構築は反映日**以降**のみ。
　根拠: L3068「禁忌: 反映日以前のコマ表は不変」, L3051。

**Q2.** ✅ 確定（**2026-09-29 改定・オーナー確定**・★実装デルタ）。反映日**以降**に設定済みの休日(holidayDates)も**消さない**（反映日の前後を問わず休日は残る）。
　休日のコマはテンプレ机を「空」とみなして突き合わせる（Q21-6）＝その日のテンプレ通常授業は置かれず、従来の休日の扱い（自動振替元など）に従う。
　~~旧: 反映日以降の休日は削除されて営業日に戻り、テンプレ授業が入る。~~（旧方式＝フラグ OFF の教室の現状実装。
　根拠: `filterTemplateOverwriteHolidayDates`（`< effectiveStartDate` だけ残す）。差分反映ではこの関数を通さない。）
　⚠️ 休日を残す結果、**休日由来の自動振替元（テンプレを根拠に算出）は新テンプレで再計算される**（旧テンプレで月曜だった生徒が
　水曜へ移れば、月曜の休日から生まれていた振替元は消え、水曜の休日から生まれる）。これを「テンプレ保存という明示操作による在庫の
　増減」として許容するかは §オーナー確認事項 #7。

**Q3.** ✅ 確定。反映日 = `templateFreezeBeforeDate` に設定され、これより前は「凍結（preTemplate基準＝旧データ）」として扱う。

## D. テンプレ展開（何を・どこまで生成するか）

**Q11.** ✅ 確定（★実装デルタあり）。**複数年一括生成・上限年度(2031)は撤廃**。テンプレは**反映日からその年度末(3/31)まで**の通常授業だけを生成する。
　理由: 長期生成は不要で上限を決める必要もない。**年度替わりでは必ずテンプレも変わる**運用のため、単年度生成で問題ない。
　現状: `regularLessonTemplate.ts` L262/271 が `maxSchoolYear = 2031` まで多年度ループ → **単年度（effectiveSchoolYear のみ）に変更**。

**Q12.** ✅ 確定。授業期間は「反映日 or 年度開始(4/1)の遅い方」〜「年度末(3/31)」。（Q11 の単年度化後は実質「反映日〜当年度3/31」）。

**Q13.** ✅ 確定。科目は生徒の**生年月日×その年度基準日**で表示科目に自動解決（学齢で算↔数など切替）。基準日＝その年度の共有開始日。

**Q14.** ✅ 確定（★実装デルタあり）。テンプレ盤面に出す対象は **「入会前」＋「在籍中」** の生徒（入会前の生徒もテンプレに配置できるようにする）。**講師も同様**（入会前＝勤務開始前も含める）。退会後・学齢外は除外。
　現状: `filterTemplateParticipantsForReferenceDate`（L209 / 呼び出し L2849, L5519）は referenceDate 時点の**在籍のみ** → **入会前(未来開始)も含める**よう条件緩和。

## E. 高3卒業・年度跨ぎ・世代交代

## F. 保存モード・履歴・入出力

**Q17.** ✅ 確定（★実装方針）。ユーザー視点では保存モードを**分けない**（overwrite/定義のみ保存の区別を意識させない）。
　ただし内部的に区別することで**挙動が軽くなる等のメリットがある場合は、内部実装としての区別は残してよい**（UI上は1つの「保存」として見せる）。

　根拠: L2920-2929。（件数上限は Q16 の3件を適用）

**Q19.** ✅ 確定。テンプレは**Excel出力/取り込み**可。取り込み時に開始日(反映日)をブック内から選んで適用。

## H. 差分反映と保留（2 行表示）— 2026-09-29 新設（Issue #72・オーナー確定 2026-09-29）

> 出典: Issue #72（緑が丘校・2026-09-29「講師が出勤不可になり担当を交代させたとき、先行生成済みの未来の週を毎週手で直している」）と

> 用語: **上段**＝新テンプレ側（盤面の机 `DeskCell` そのもの）、**下段**＝既存側（保留マップに退避した保存前の机）、
> **保留（2 行）**＝1 つの机に上段と下段が並んでいる状態、**生きている生徒**＝`lesson.studentSlots` に居る生徒（欠席・振無休などで
> 出欠記録 `statusSlots` へ移った生徒は数えない）。

### Q21. 反映の単位と突き合わせ規則 ✅ オーナー確定（-5〜-8 は暫定補完）

1. **反映日（`effectiveStartDate`）より前は一切変更しない**（Q1 維持）。対象は反映日以降のセルだけ。
2. テンプレの机と盤面の机は、**同じコマ（日付×時限）の中の机番号（位置 index）どうし**で比べる。
   **講師名や旧テンプレ履歴は比較の鍵に使わない**（講師交代が主用途なので講師名は鍵にできない。旧テンプレとの差は当たり前の事象
   なので、それ自体を衝突扱いしない）。
3. 机ごとの振り分け（オーナー確定）:

   | 盤面の机 | テンプレ机（同じ index） | 結果 |
   |---|---|---|
   | 手入力の印**なし**（Q22） | 何でも（空を含む） | **テンプレ机で置き換え**（テンプレ机が空なら空になる） |
   | 印**あり** | 空 | **既存をそのまま残す**（1 行） |
   | 印**あり** | あり・**中身が同じ**（Q23） | **テンプレを採用し印を外す**（1 行・Q23-3） |
   | 印**あり** | あり・**中身が違う** | **保留（2 行）**：上段＝テンプレ、下段＝既存。机の背景を**緑**にして重複を示す |
   | 削除記録（tombstone: `teacher=''` かつ `teacherAssignmentSource='deleted'`）**だけ**で、生徒・出欠記録・メモが無い空き机 | 空 | **黙って消す**（tombstone を外す） |

4. **詰め替え（pack）で机がずれている**と衝突（保留）が増えるが、下段の移動／「既存を採用」で片づく前提で**許容する**（オーナー確定）。
5. **暫定**：テンプレ机は、**保存時点で保持している抑止を当てた後の姿**で突き合わせる。具体的には
   通常授業の抑止キー（`suppressedRegularLessonOccurrences`＝生徒×科目×日×時限。欠席・削除・移動で積まれる）に一致する生徒を外し、
   丸ごと振替の日単位抑止（`TEMPLATE_TEACHER__DAY__<日付>`）がある日は生徒のいない足場講師を外す（盤面の再マージ
   `overlayBoardWeeksOnScheduleCells` と同じ当て方・同じ順序＝抑止 → 足場講師 strip）。
   理由: 欠席・削除した通常授業が上段に湧くと、同じ生徒が上段（生きている）と出欠記録に二重に出る（INV-12）。Q10（抑止を保持）が前提。
6. **暫定**：休日のコマ（`holidayDates`・定休日で `forceOpenDates` でない日）は、テンプレ机を**空**とみなす
   （＝印なし机は空になり、印あり机は残る）。Q2 で休日を残すことの帰結。
7. **暫定**：対象は**保存時点で盤面に生成済みの週**（先行生成は最大 26 週先）の反映日以降のセル。未生成の週は、後で盤面を開いたときに
   新テンプレから生成される（保留は生じない）。
8. **暫定（§オーナー確認事項 #1・最重要）**：「既存をそのまま残す」机・下段に、**旧テンプレ由来の通常授業の生徒**（印を持たない
   `lessonType='regular'` の生徒）が居る場合の扱い。新テンプレがその生徒を**別の机・別の時限・別の曜日**に置いていると、残した机の
   生徒と新しい位置の生徒が**二重に数えられる**（例: 月 2 限の机 3 にメモ〔印〕があり、テンプレで生徒 A を月→水へ移した → 月の机 3 に
   A が残り、水にも A が入る）。暫定案＝**残す机（1 行）からは印を持たない旧テンプレ由来の通常生徒を外す**（その席の出欠記録・メモは残す）。
   下段（2 行）の中では外さない（下段は数えないので二重計上にならず、解決時に Q26 の一意性検査で止める）。

### Q22. 「手入力の印」の定義 ✅ オーナー確定（コードで確認済み・判定単位の整理は暫定）

机が次のどれか 1 つでも持てば「印あり」。**判定は純関数に一本化**する（仮称 `resolveDeskManualInputMark`。理由の一覧も返し、保存前の
件数表示とテストに使う）。

- **生徒単位**（`lesson.studentSlots` の生徒）:
  - 種別が `makeup` / `special` / `trial` / `extra`（振替・講習・体験・増コマ）
  - `manualAdded`（手動追加）
  - `sameDayMoveSourceDate`（同じ日の別机・別時限へ動かした通常授業。同一コマ内の机替えにも付く）
  - `makeupSourceDate`（別の日へ動かして振替に変換された）
- **机単位**:
  - `manualTeacher` または `teacherAssignmentSource` が `manual` / `manual-replaced` / `schedule-registration` / `deleted`
    （講師を手で置いた・入れ替えた・QR 自動割当・削除）
  - `statusSlots` に出欠記録がある（`absent` / `absent-no-makeup` / `attended` / `moved` / `holiday` のどれでも）
  - `memoSlots` に空でないメモがある
  - `suppressedRegularLessonOccurrences` に**その日の通常授業の削除記録**がある。**暫定**：抑止キーには机が無いので、
    「このコマ（日×時限）の抑止キーのうち、**テンプレ机（抑止前）の生徒×科目に一致するもの**」をその机の印として帰属させる。
- 既存の週トリム判定 `weekHasManualBoardData`（`boardWeekTrim.ts`・週単位）とは**目的が違う**（あちらは保守的に「少しでも痕跡があれば保持」）。
  印の判定をそちらへ寄せたり、そちらを印の判定で置き換えたりしない（週トリムの安全側を崩さない）。

### Q23. 「中身が同じ」の定義と「印を外す」の意味（-1 はオーナー確定、-2〜-4 は暫定）

1. **中身が同じ**＝**講師・生きている生徒・科目が一致**。**印の有無は無視**する（オーナー確定）。
2. **暫定**：講師は講師 ID（`teacherAssignmentTeacherId` / 名簿 ID）で、無ければ名前で比べる。生徒は `managedStudentId` 優先・無ければ名前で比べ、
   **種別（`lessonType`）も比べる**（既存が振替の A・テンプレが通常の A は「違う」＝保留にする。同じとして採用すると振替の消化が消え、
   保存だけで在庫が 1 増える＝Q25 に反する）。**席順（ペアの左右）は問わない**。授業時間（`noteSuffix`）・出欠記録・メモは比べない。
3. **暫定**：**「印を外す」**＝講師の手置き印（`manualTeacher`・`teacherAssignmentSource`・`teacherAssignmentSessionId`・
   `teacherAssignmentTeacherId`）と、生徒の印（`manualAdded`・`sameDayMove*`）を外してテンプレ由来として扱うこと。
   **出欠記録とメモは消さずに机へ残す**（在庫〔欠席由来〕と日程表の「休」表示を守るため。Q25）。
4. **暫定（§オーナー確認事項 #3・ユーザビリティ）**：主用途（講師交代）の典型形で保留が大量に出る点の扱い。テンプレの
   **講師だけの机（足場講師）**に先々の振替・講習が置かれている机は、講師交代でほぼ全部「印あり＋中身が違う」になり 2 行になる
   （上段＝新講師だけ・下段＝旧講師＋振替）。確定規則どおりの解決は「下段の生徒を上段へ移動 → テンプレを採用」または
   「既存を採用 → 講師を手で差し替え」の 2 手。妥協案は §懸案＆妥協案 を参照。

### Q24. 保留データの置き場と保存 ✅ オーナー確定（-3〜-5 は暫定）

1. 下段（既存）のデータは机（`DeskCell`）の中に入れず、**別マップ**に保存する。キーは**コマ ID × 机 ID**（オーナー確定）。
   仮称 `templatePendingDesks: Record<"<cellId>::<deskId>", { lower: 既存机の写し; effectiveStartDate; createdAt }>`。
   `lower` は保存前の机の講師・講師の印・`lesson`・`statusSlots`・`memoSlots` をそのまま持つ。
2. **保存スナップショットに含め、端末をまたいでも保留が残る**。**リアルタイム同期（ポップアップ）も対象**（オーナー確定）。
3. **暫定（配線の網羅）**：新フィールドは既存の `groupClassEntries`（optional の別マップ）と同じ流儀で、少なくとも次の経路すべてに通す。
   1 つ漏れると**黙って消える**（`spec-makeup-stock.md` §B-2-3 の「専用フィールドは約 40 箇所の配線が要り、1 つ漏れると黙って消える」の教訓）:
   `PersistedBoardState` 型／`workspaceStore` の分割保存（boardStock 側の Pick）と分割読込／`App` のダーティ署名／
   `onBoardStateChange` の publish 全経路（commit・undo/redo・テンプレ保存）／undo・redo の履歴エントリ（`applyHistoryEntry`）／
   JSON フルスナップショットの書き出し・読み込み／サーバー自動バックアップ・一段スナップショット復元／リアルタイム同期。
   **欠けた経路を検出する配線テスト**（保存 → 読込 → publish → undo の往復で `templatePendingDesks` が deep-equal で残る）を必須にする。
4. **暫定**：保留のある週は週トリム（`trimBoardWeeksForMemory`）で**破棄しない**（破棄すると保留マップのキーが宙に浮く）。
5. **暫定**：保留マップのキーが指す机が盤面に無い（週が再生成された・机数が減った等）ときは、**黙って捨てない**。
   開発者向けの整合チェックで検出して知らせる（実データを消さない）。
6. 既存データへの影響: 新フィールドは optional。**未設定＝保留なし**で後方互換。移行処理は不要。

### Q25. 参照範囲と在庫 ✅ オーナー確定（INV 案は `spec-invariants.md` INV-06 拡張・INV-13 案）

1. **日程表（生徒・講師）、盤面 PDF、保護者向け表示、予定回数・実績回数の計算は上段（テンプレ側）だけを見る**。下段は**盤面画面専用**（オーナー確定）。
   **暫定**：盤面共有（`BoardShareScreen`）・給与／交通費の集計・自動割振ルールの警告判定も上段だけ（下段は「実配置」ではない）。
2. **予定回数（通常回数）は上段で数える**（オーナー確定）。
3. **在庫（オーナー確定・INV-06 拡張案）**:
   - 保留中、**下段に置かれている振替・講習は消化済みのまま**扱う（未消化に戻さない。戻すと未消化が増えて見え、二重配置の事故になる）。
   - 上段は通常授業なので**在庫を動かさない**。上段の生徒を欠席にしたときだけ、既存の欠席処理で在庫が動く。
   - **下段を削除すると、既存の削除処理どおり在庫へ戻す**。
   - ⇒ **テンプレ保存そのものでは、どの生徒×科目の未消化振替・未消化講習も増減しない**（保存前後で完全一致）。
4. **暫定（§オーナー確認事項 #4）**：上記 1（在庫計算は上段だけ）と 3（下段の振替は消化済み）を両立させるための解釈。
   在庫の**発生**のうちテンプレを根拠に算出するもの（休日・占有の自動振替元）は上段＝テンプレで数え、
   在庫の**消化**（振替コマ）と**欠席由来の在庫**（`absent` 記録から算出）は**下段も数える**。振替の残数は盤面の走査で決まる
   （`collectMakeupUsageByKey` 等）ため、走査に下段を含めないと保存しただけで在庫が増える。講習の残数は提出希望数±デルタ台帳で
   決まり盤面を走査しないので、下段の講習は何もしなくても消化済みのまま。

### Q26. 解決操作 ✅ オーナー確定（-4・-5 は暫定）

1. 保留の机ごとに **「テンプレを採用」「既存を採用」** の 2 ボタン。
   - **「既存を採用」**＝上段を取り下げ、下段を机に戻す。**希望回数の補正はしない**（既存の「削除」は希望回数 −1 なので意味が違う）。
     **暫定**：取り下げた上段のテンプレ生徒には抑止キーを積み（再マージで湧かせない）、振替在庫は生まない（欠席ではない）。
     結果、その生徒は日程表の回数表で「予定より 1 少ない」として残る（室長への合図。§オーナー確認事項 #5）。
   - **「テンプレを採用」**＝下段を捨てる。**暫定**：下段の振替・講習は既存の「削除」と同じ在庫処理（在庫由来は未消化へ戻す・
     手動追加は戻さない）。下段の通常授業（旧テンプレ由来・同日移動）は**希望回数を動かさない**（上段にテンプレの通常授業があるため）。
     下段の会計を持つ出欠記録は Q28 の引き継ぎ規則で机に残す。
2. **上段（テンプレ生徒）の生徒メニュー**：休み・振無休・移動・削除（既存の意味どおり。削除は希望回数 −1）。
3. **下段のメニュー**：メモだけなら「削除」のみ（確認ダイアログ → 削除）。生徒がいるなら「削除」「移動」。
   **出席・休み・振無休は下段に付けられない**。
4. **暫定**：解決操作（採用ボタン・下段の削除/移動・上段の休み/振無休/移動/削除）の結果、**同じコマに同じ生徒が 2 か所で生きる**なら
   実行せずに止めて理由を出す（INV-12。既存の `findDuplicateStudentInCellByKey` と同じ検査）。
5. **暫定**：2 行の机では、講師メニュー・講師 D&D・講師セル選択を**無効**にする（先に採用ボタンで片づける）。他の机から 2 行の机
   （上段の空席を含む）への生徒の移動・D&D の着地も**不可**。
6. 解決操作・採用ボタンは **Undo（戻す／やり直し）の対象**（INV-03。1 操作 1 適用・版数 bump・`userInitiated:true` の publish は
   既存の `commitWeeks` と同じ）。

### Q28. 1 行に戻る条件と引き継ぎ ✅ オーナー確定（-4〜-6 は暫定）

1. **どちらかの行に「生きている生徒」がいなくなったとき 1 行に戻る**。欠席・振無休にした生徒は出欠記録になり、生きている生徒に数えない。
2. **残った行の講師と生徒が机になる**。
3. **出欠記録の引き継ぎ**：「上段の休み・振無休の記録」＋「下段が元から持っていた会計を持つ記録（`absent` / `absent-no-makeup` / `attended`）」を
   引き継ぎ、**表示専用の記録（`moved` / `holiday`）は捨てる**。**出欠枠（2）を超える場合は合流を止め**「先に下段を片づけてください」と知らせる

4. **暫定**：両方の行に生きている生徒がいないまま 1 行に戻るとき（例: 下段＝欠席記録だけ・上段＝欠席者が抑止で消えて講師だけ）は、
   **上段（テンプレ）の講師**を残す。
5. **暫定**：下段のメモは、メモ枠（2）に入る範囲で机へ引き継ぐ。入らなければ出欠と同じく合流を止める。
6. **暫定（§オーナー確認事項 #6）**：突き合わせの**時点で**すでに片方の行に生きている生徒がいない場合（例: 下段＝手置き講師だけ・
   下段＝メモだけ・下段＝削除記録だけ）は、2 行を作らずに**その場で本条の規則で 1 行にする**。1 行になった机の数は保存後の
   メッセージで「○机は既存の手入力をテンプレで置き換えました」と別に数えて見せる（黙って消さない）。

### Q29. 保留中の再保存 ✅ オーナー確定

1. **（最重要）残す机に居る旧テンプレ由来の通常生徒**（Q21-8）：新テンプレで別の机・時限・曜日へ移した生徒が、メモ等の印がある机に残って二重に数えられる。
   選択式：(a) 残す机からは外す（推奨）／(b) 残す（日程表で 2 回数えられる）／(c) その机も保留（2 行）にする。
2. **Q10 の台帳・抑止**：反映日以降の抑止・希望回数補正・手動振替調整を、差分反映では一括クリアせず保持する（推奨）でよいか。
3. **主用途で保留が大量に出る件**（懸案 1）：妥協案 A／B＋C（推奨）／D のどれにするか。
4. **在庫の数え方の解釈**（Q25-4）：「在庫計算は上段だけ」と「下段の振替は消化済み」を両立させるため、在庫の消化と欠席由来の在庫だけは下段も数える、でよいか。
   あわせて、**出欠記録の置き場**：確定どおり下段へ入れる（保留中はその生徒の日程表から「休」表示が消える）か、
   会計を持つ記録（`absent` / `absent-no-makeup` / `attended`）だけは机に残す（日程表の「休」表示と在庫が保存前後で変わらない）か。
5. **「既存を採用」の回数表**（Q26-1）：取り下げたテンプレ生徒は希望回数を補正しないので、回数表で「予定より 1 少ない」が残る。これを室長への合図として受け入れるか。振替在庫を生まない、でよいか。
6. **作成時点の即時合流**（Q28-6）：下段に生きた生徒がいない机（手置き講師だけ・メモだけ等）は 2 行にせず、上段（テンプレ）＋下段の記録・メモで 1 行にする、でよいか（手置き講師は消える）。
7. **休日由来の自動振替元の再計算**（Q2 の注記）：休日を残すことで、テンプレ保存により休日由来の振替元が増減しうる。明示操作による変化として許容するか、保存時に固定（旧テンプレでの振替元を台帳へ確定）するか。
8. **保留中の他操作**（Q31 の表）：休日設定・全コマ削除・丸ごと振替を止める／詰め替えで保留の机を固定する／講師操作を無効にする、の各既定でよいか。
9. **旧版タブのすき間**（Q33-1）：全教室昇格の前に、リアルタイム同期で保留入りデータを受けた旧版タブの保存を止める手立て（例: 保存時に保留マップの欠落を検出して拒否）を入れるか。
10. **INV の扱い**（`spec-invariants.md`）：INV-02 の例外文言の改定、INV-06 の拡張、INV-13 の新設（または INV-01/05 への注記で代える）の承認。
11. **保存前レポート PDF**（Q32-3）：維持（見出し変更）でよいか。
12. **盤面共有・給与/交通費・自動割振の警告**（Q25-1 暫定）：下段を見ない（上段だけ）でよいか。
