## 0. はじめに

1. **このアプリでできること** … 1 週間分のコマ表（盤面）を作り、生徒・講師それぞれの日程表を印刷・共有する。
   振替と講習の残り回数もアプリが数える。
2. **使い始める前に** … ログインする教室を確認する。複数教室を扱う場合、**いま開いている教室**にしか変更は入らない。
3. **困ったときは** … 画面右上（コマ表・日程表の両方）の「要望・報告」ボタンから、不具合・要望・質問を送れる。
   → 第 9 章。

## 1. 画面の全体像

1. **メニューの 5 画面** … コマ表／基本データ／特別講習データ／自動割振ルール／バックアップ・復元・初期設定。
2. **コマ表（盤面）が中心** … 日付×コマ×机のマス目に、生徒の授業を置く。ラベル `通)` `振)` `講)` で種類を見分ける。
3. **日程表は別タブ** … 盤面から開く生徒用・講師用の一覧。印刷・共有はここから行う。

## 2. 基本データ（生徒・講師・教室の設定）

1. **生徒** … 氏名・学年・入塾/退塾日・受講科目を登録する。在籍期間外の日には自動で並ばない。
2. **講師** … 氏名と担当科目。机の割り当てはコマ表側で行う。
3. **削除の注意** … 講習を提出済みの生徒を消すと記録が追えなくなるため、削除時に確認が出る。〔未執筆〕
4. 参照: `docs/spec-basic-data.md`。

## 3. 通常授業（テンプレート）

1. **考え方** … 毎週くり返す通常授業は「テンプレート」に登録し、在籍期間中の各週へ自動で並ぶ。
2. **個別の調整** … その週だけの変更は盤面で直接動かす。手で動かした内容はテンプレートの再反映で消えない。
3. **休講日・5 週目** … 休みの日は授業を置かない設定にできる。週が 5 回ある月でもテンプレートどおりに並ぶ。
4. 参照: `docs/spec-board-regular-placement.md` / `docs/spec-template-behavior.md`。

## 4. 欠席と振替

1. **欠席を登録すると振替が 1 回たまる** … コマは残したまま「欠」と表示し、席は他の生徒に使える。
2. **振替を置く** … たまった振替（未消化）から日付とコマを選んで盤面に置く。置くと残りが 1 減る。
3. **元に戻す** … 置いた振替を消すと未消化に戻る。戻らないときは第 9 章から報告する。
4. 参照: `docs/spec-makeup-stock.md`。

## 5. 特別講習（季節講習）

1. **希望の受け付け** … 生徒・保護者は QR コードから希望科目と回数を提出する。提出内容は教室ごとに分かれている。
2. **コマを組む** … 提出された回数を「未消化」として持ち、盤面へ置いていく。削除すると希望が 1 減る／ストックに戻す操作がある。
3. **残数の見方** … 一覧で「希望・実績・未消化」を確認する。数え方は通常授業と講習で呼び方が違う（予定数／希望数）。
4. 参照: `docs/spec-lecture-stock.md` / `docs/spec-special-session-submission.md`。

## 6. 自動割振

1. **できること** … 未消化の振替・講習を、条件に合う空きコマへまとめて置く。
2. **ルールの 2 区分** … 「優先事項」はなるべく守る、「制約事項」は破らない（置けなければ未消化のまま残る）。
3. **結果の確認** … 置かれた内容は普通のコマと同じように手で直せる。
4. 参照: `docs/spec-auto-assign-rules.md`。

## 7. 日程表と印刷

1. **生徒日程表／講師日程表** … 別タブで開き、期間・人物を選んで表示する。最新の盤面に自動で追従する。
2. **印刷** … A4 が基本（量が多い日は A3 に切り替わる）。空フォーマット（白紙）も印刷できる。
3. **共有** … 講師日程共有・配布用盤面で、閲覧専用のページを渡せる。
4. 参照: `docs/spec-schedule-pdf.md` / `docs/board-pdf-design.md`。

## 8. 保存・バックアップ

1. **保存は手動** … 変更は「保存」ボタンを押すまでサーバーに入らない。画面を閉じる前に保存する。
2. **自動バックアップ** … サーバー側で定期的に控えを取っている。戻す操作は開発者が行う（利用者は操作しない）。
3. **同時に開かない** … 1 つの教室を複数端末で同時に編集すると、後から保存した方で上書きされる。
4. 参照: `docs/spec-save-restore.md`。

## 9. 要望・報告・質問の送り方

1. **ボタンの場所** … コマ表のツールバー右側、日程表タブのツールバー右側。どちらも同じ画面が出る。
2. **3 つの種類** … 「不具合・おかしい」「追加してほしい・要望」「使い方の質問」。内容は必須。
   生徒名・日付・コマ・やった操作と起きたことを具体的に書くほど確認が早い。
3. **送ったあと** … 開発者にすぐ通知が届く。**回答は開発者が確認してから返す**（すぐには返らない・自動返信はしない）。
   回答が用意できるとアプリ起動時などにお知らせが出る。
4. 参照: `docs/spec-developer-report.md`（§B・§G）。

## 10. よくある質問（QA）

1. 開発者が承認・公開した質問と回答をここに追記していく（公開の基準は `docs/spec-developer-report.md` §G-4）。
2. 個別教室の具体名・生徒名は載せない（一般化した書き方にする）。
3. 〔未執筆〕

## 11. 用語のたいおう表（利用者の言葉 ↔ 画面の言葉）

1. 「コマ」「限」「机」「未消化」「ストック」「テンプレ」など、利用者が口頭で使う言い回しと画面表示の対応を並べる。
2. 報告・質問の文面を読み解くとき、および回答を書くときの語彙をそろえるために使う。
3. 〔未執筆〕
